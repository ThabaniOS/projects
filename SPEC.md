# ThabaniOS v4 — Two-Way Project System

**Owner:** Thabani · **Repo:** `ThabaniOS/projects` (private) · **Written:** 2026-10-26
**Purpose of this file:** the single brief every build session works from. If something here conflicts with an older doc in the repo, this file wins.

---

## 1. Problem being solved

v1–v3 were one-way. Project state lived in `outputs/*.md` on the laptop, `npm run brief` generated `status.json` locally, then a manual push. Telegram could only *capture* into inbox files or *read* `status.json`. Any write from Telegram was either an inbox line that needed manual processing, or would be overwritten by the next local regeneration.

**v4 fix: the repo is the source of truth.** One structured markdown file per project lives in the repo. Telegram, the dashboard and Claude Code are all just editors of those files. The laptop is optional.

---

## 2. Architecture

```
Telegram ──▶ Vercel function /api/telegram ──▶ Claude API (tool use)
                                                   │
                                     reads/writes via GitHub Contents API
                                                   ▼
                                   ThabaniOS/projects  (projects/*.md)
                                                   │  push
                                                   ▼
                     GitHub Action: build status.json ──▶ Vercel redeploys dashboard
```

- **Bot layer:** a serverless function in the same Vercel project as the dashboard. Replaces the n8n `ThabaniOS Bot` workflow (ID `0JvrGGLAEPNbqRou`).
- **Data layer:** `projects/<id>.md` (active, paused, pipeline, live). Sunset projects are **not** in the repo — they live in the local `ThabaniOS/archive/` folder.
- **Derived data:** `status.json` is generated by a GitHub Action on every push to `projects/**`. Nothing generates it locally any more. `scripts/generate-status.js` is retired.
- **Inbox capture** (`edge:`, `idea:`, `project:`) keeps writing to `inbox/*.md` exactly as today.

### Important: one bot, two senders
The same Telegram bot token is used by the **Raiis Payment Reminder** n8n workflow (send-only, no trigger). That stays on n8n and keeps working. Only the inbound webhook moves. A bot can have exactly one webhook, so the n8n `ThabaniOS Bot` workflow (Telegram Trigger) **must be deactivated** at cutover, or n8n and Vercel will fight over `setWebhook`.

## 3. Project file schema

```markdown
---
id: leola                     # = filename, kebab-case, immutable
name: Leola Atelier
ticker: LEO                   # 2–4 caps, unique; used as task-ID prefix and Telegram shorthand
status: active                # active | pipeline | live | paused
category: client-direct       # raiis | mb-digital | client-direct | venture | personal
client: Lara (Leola Atelier)  # optional
priority: 1                   # 1 = now, 2 = this month, 3 = when there's room
finish_line: Store live on Shopify with payments + Klaviyo before stock lands
deadline: 2026-11-30          # optional, ISO date
updated: 2026-10-26           # set by every write
---

## Tasks
- [ ] LEO-1 Finish Shopify store setup
- [x] LEO-2 Pick payment gateway (done 2026-10-28)

## Log
- 2026-10-26: Migrated to ThabaniOS v4.

## Notes
Free text. Context, decisions, links to local raw/ folders.
```

**Rules**
- Task IDs are `<TICKER>-<n>`, never reused, never renumbered. New task = max(n)+1.
- Completed tasks stay in the list (ticked, with `(done YYYY-MM-DD)`) until the weekly digest rolls them into the log.
- Log is append-only, newest at the bottom, one line per event.
- `status: sunset` is never written into the repo. Sunsetting = move the file to the local archive (bot removes it from the repo and tells Thabani to pull it into `archive/` locally — see §5).
- A JSON Schema (`schema/project.schema.json`) validates frontmatter. The bot and the Action both refuse to commit a file that fails validation.

## 4. Telegram bot

### Access
- Allowlist: Thabani's Telegram chat ID only. Every other sender gets no reply.
- Telegram `secret_token` set on `setWebhook`; the function rejects requests without the matching `X-Telegram-Bot-Api-Secret-Token` header.
- Secrets in Vercel env vars: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_ALLOWED_CHAT_ID`, `GITHUB_TOKEN` (fine-grained PAT, contents read/write on `ThabaniOS/projects` only), `ANTHROPIC_API_KEY`.

### Claude tools
| Tool | Does | Writes? |
|---|---|---|
| `get_focus` | Reads `status.json`; ranks open tasks across active projects by priority, deadline, staleness | No |
| `get_project(id\|ticker)` | Returns one project file | No |
| `list_projects(status?)` | Compact list | No |
| `update_tasks(id, done[], add[], edit[])` | Tick, add, reword tasks | Yes |
| `add_log(id, text)` | Append a log line | Yes |
| `set_fields(id, {status, priority, finish_line, deadline})` | Change frontmatter | Yes |
| `create_project(...)` | New file from template | Yes |
| `sunset_project(id, reason)` | Removes from repo, returns content for local archive | Yes |
| `capture(kind, text)` | Existing inbox capture | Yes (no confirm) |

### Confirm-before-commit (Thabani's decision, 2026-10-26)
1. Claude proposes the change → function renders a plain-language diff in Telegram:
   ```
   LEO · Leola Atelier
   ✓ LEO-1 Finish Shopify store setup
   + LEO-4 Set up payment gateway
   + LEO-5 Open Klaviyo account
   ```
2. Inline buttons: **Confirm** / **Edit** / **Cancel**.
3. The pending change is stored server-side keyed by a short ID (Vercel KV or a `pending/` JSON file in the repo) with a 30-minute expiry.
4. Confirm → commit via Contents API with the file's current `sha` (optimistic lock; if the sha changed, re-read and re-propose).
5. After commit, reply with the commit link and an **Undo** button (reverts that one commit).
6. `capture` is the only write that skips confirmation.

### Model routing (cost control)
- Haiku 5.5 for routing, lookups and task updates.
- Sonnet 5.5 only for `get_focus` and the weekly digest.
- Load only the files a request needs. `get_focus` reads `status.json` (compact), not every project file.
- Prompt caching on the system prompt and tool definitions.

### Example exchanges
- *"what should I focus on"* → top 5 open tasks across projects with one-line reasons.
- *"leola"* or *"what's next on LEO"* → finish line + open tasks.
- *"LEO: shopify done. next is payment gateway and klaviyo account"* → diff, confirm.
- *"sunset HOD"*, *"pause vending"*, *"new project: X for client Y"* → diff, confirm.

## 5. Dashboard v4

Same Vercel project and URL (`dashboard-iota-mauve-68.vercel.app`). Static page reading `status.json`.
- **Focus now** panel at the top (same ranking as `get_focus`).
- Project cards grouped by status: Active → Pipeline → Live → Paused (collapsed).
- Each card: ticker, name, finish line, open-task count, next 3 tasks, days since `updated` (amber > 14 days, red > 30).
- Protected with Vercel Authentication (Hobby supports it) — the data contains client names.
- No editing from the dashboard in v4. (Later phase: tick tasks from the page via the same confirm flow.)

`status.json` shape (built by the Action):
```json
{ "generated": "...", "projects": [ { "id","name","ticker","status","category","priority",
  "finish_line","deadline","updated","open_tasks":[{"id","text"}],"done_count","last_log" } ] }
```

---

### Compatibility until Phase 3/4
`status.json` also carries the v3 fields (`title`, `type`, `next_action`, `blocker`, `date_canvassed`, `last_modified`) so the current `index.html` and the n8n query bot keep working. Drop them once the v4 dashboard and Vercel bot are live.

### Phase 2 note
`vercel.json` currently rewrites every path to `index.html`. Change it to exclude `/api/` before adding the bot function, e.g. `{ "source": "/((?!api/).*)", "destination": "/index.html" }`.
